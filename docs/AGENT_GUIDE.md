## 0. Роль

Ведущий инженер проекта Asset Doctor. Сначала читаешь, потом планируешь, потом пишешь код.
Перед любым крупным решением (выбор библиотеки, структура, схема данных) — короткое
согласование, а не действие по умолчанию. Маленькие коммиты, тесты на ядро анализа, без
переусложнения.

## 1. Что строим

**Asset Doctor** — браузерный аудит и оптимизация ассетов для HTML5-игр (PixiJS / Phaser).
Загрузил ассеты → за секунды видишь карту проблем (пустота в атласах, неоптимальные форматы,
оверсайз-текстуры, лишний VRAM и draw calls) и сколько веса можно срезать → платишь, чтобы
скачать оптимизированную папку.

**Почему это работает:**
- **Прямых конкурентов нет.** TexturePacker пакует, но не аудирует. Профайлеры живут внутри
  Unity/Unreal. Для HTML5/Pixi standalone-аудита ассетов нет.
- **Pain-killer.** Разработчик приходит с горящей болью (тяжёлый билд / лаги на бюджетном
  Android), а не с задачей, которую надо себе продавать.
- **Моат — глубина рендер-пайплайна:** эффективность упаковки (MaxRects, trim, power-of-two),
  PMA/premultiplied alpha, формат под платформу (WebP/AVIF), Spine (мультитрек, тяжёлые меши),
  и главное — **render-probe**: реальная загрузка ассета в offscreen-WebGL через Pixi и замер
  фактического футпринта. Этого статические анализаторы не дают в принципе.

## 2. Архитектурные инварианты (не нарушать без явного согласования)

1. **Тяжёлое — в браузере, лёгкое — на сервере.** Анализ локальной папки идёт клиентски,
   ассеты по умолчанию **не покидают устройство**. Приватность (снимает страх за IP) +
   обнуляет косты на обработку.
2. **Бэкенд намеренно тонкий.** Только auth, биллинг (Stripe), история отчётов (метрики, не
   картинки), лицензии. Никакой тяжёлой обработки изображений в базовом сценарии.
3. **Объективность.** Инструмент ничего не генерирует и не «рисует» — он измеряет и выдаёт
   вердикты по порогам. Нет ответственности за качество генерации.
4. **Instant wow.** Первый ценный результат — ≤10 секунд после drag-drop, без регистрации.
5. **Ключевой инсайт продукта:** вес файла на диске ≠ нагрузка на GPU. PNG 2048×2048 = 16 МБ
   VRAM (`w×h×4`, RGBA8888) независимо от сжатия, +33% с мипмапами. Разработчики этого не
   видят — мы показываем.

## 3. Стек

**Frontend / клиентский анализ:** TypeScript · React · Vite · PixiJS v8 (render-probe и
WebGL) · Web Workers (анализ вне main-thread) · WebAssembly-кодеки (libwebp-wasm для
транскодинга) · File System Access API + фолбэк `<input webkitdirectory>` · Canvas 2D (оверлеи).

**Алгоритмы:** MaxRects (перепаковка) · pHash/dHash (дубликаты) · libwebp/libavif (транскодинг).

**Backend (отложен до Phase 2):** Go — первый боевой Go-сервис (Chi или `net/http`,
`stripe-go`, sqlc/pgx). Альтернатива для скорости старта — NestJS с последующей миграцией.
**Решение фиксируем перед Phase 2, не сейчас.**

**Данные/инфра:** PostgreSQL · Redis (сессии, rate-limit, очередь) · object storage R2/S3
(только опциональные серверные артефакты) · Docker · фронт на Cloudflare Pages/Vercel,
Go-сервис на Hetzner/Fly · Stripe.

**Качество:** Vitest (фронт + ядро анализа) · Playwright (e2e) · Go testing + golden-файлы ·
ESLint/Prettier · golangci-lint.

> Ограничение «только базовый Tailwind без arbitrary-значений» относилось к песочнице
> артефактов Claude.ai. В реальном Vite-репозитории Tailwind можно использовать полноценно.

## 4. Режимы ингеста и профайлинга

Жёсткое ограничение браузера: **глубоко инструментировать можно только страницу, внутри
которой исполняешься сам** (same-origin). Поэтому ингест — три режима с разной достоверностью
и ценой.

**Режим A — Локальная папка → клиент, приватно.** Статический анализ. Лид-магнит.
(Базовый, проектируется первым.)

**Режим B — URL → серверный headless.** Чисто в браузере не выйдет: CORS не даст прочитать
пиксели чужого домена (tainted canvas), а кросс-доменный `<iframe>` — чёрный ящик. Решение:
сервер (Playwright/Puppeteer или Go-аналог) открывает URL, перехватывает сетевые запросы игры,
тянет ассеты к себе. Для *публичной задеплоенной* игры это норм. Бонус: виден реальный манифест
загрузки. Камни: прогрессивная подгрузка, запакованные бандлы (Unity `.data`, base64),
анти-бот, авторизация.

**Режим C — SDK-сниппет / Chrome-расширение → реальное устройство, непрерывно.** Исполняется
*внутри* игры на *реальном* девайсе. RUM для игр и главный двигатель подписки.

**Две категории рантайм-метрик по достоверности:**
- **Структурные / GPU-workload** — через обёртку WebGL-контекста (перехват `drawElements`,
  `texImage2D`, `useProgram`, как Spector.js): draw calls/кадр, лишние state changes,
  биндинги и аплоады текстур, число и время компиляции шейдеров, overdraw, треугольники,
  оценка VRAM по живому набору текстур. **Device-independent** — валидны хоть из headless,
  хоть из расширения. Основная масса находок.
- **Тайминговые** — FPS, frame time, jank, JS heap/GC. **Достоверны только на реальном целевом
  устройстве.** FPS с датацентрового GPU ничего не говорит о бюджетном Android. `EXT_disjoint_timer_query`
  спотти, `performance.memory` только Chromium и грубый.

**Слой корреляции (линтер становится доктором):** сшивать статику и рантайм в один вывод с
доказательством + фиксом + оценкой эффекта.

**Прагматичный порядок:** статика (есть) → расширение/SDK для структурного рантайма на реальном
девайсе → URL-краул последним.

## 5. Дизайн-направление UI

Метафора — **рентген-кабинет**. Светлая «карта пациента» как оболочка + тёмный лайтбокс-вьюер,
где атлас читается как снимок на просвет, а проблемы подсвечены как аномалии.

**Сигнатура — film-viewer** (атлас-снимок с горящими проблемными зонами), а НЕ большая цифра
экономии. Число экономии работает в шапке и в CTA, но герой — диагностический снимок.

**Токены:**
- Палитра: bg `#E7ECF1`, panel `#FFFFFF`, line `#DCE3EA`, ink `#16202A`/`#566472`, film
  `#0C1116`, teal `#0E8C8C`, CTA-green `#15A06A`.
- Severity: crit `#E5484D`, warn `#D98A00`, ok `#1F9D63`, info `#2B8FC9`.
- Шрифты: **Space Grotesk** (display) · **IBM Plex Sans** (body) · **IBM Plex Mono** (все
  числа/метрики/имена файлов).
- Слои оверлеев: пустое место — красная заливка+пунктир; прозрачные поля — жёлтый пунктир;
  bleeding — бирюзовый пунктир. Клик по находке подсвечивает её зоны на снимке.

## 6. Фазы

0. **Валидация** — лендинг + waitlist + ручной прогон чеклиста на реальных играх с itch.io.
1. **Бесплатный диагноз (MVP)** — импорт папки, проверки P0, визуализация. ← **мы здесь**
2. **Платный фикс (Pro)** — перепаковка, транскодинг, биллинг (тогда же решаем Go vs Nest).
3. **CI / подписка** — CLI, бюджет-гейт, GitHub Action, сравнение билдов «до/после».
4. **Расширение** — Spine, AVIF, режимы B/C (URL-краул, SDK/расширение), движко-агностик, playable.

## 7. Первые задачи

### Milestone 0 — Репозиторий и память проекта
- Осмотреть структуру, согласовать с целевой раскладкой: `apps/web`, `apps/api`,
  `packages/{analysis,probe,fix,parsers}`, `workers/fix-worker`, `fixtures/sample-projects`.
- Поднять `apps/web` на Vite + React + TS.
- Создать сжатый `CLAUDE.md` в корне.

### Milestone 1 — Вертикальный срез
Локальная папка → реальный диагноз → film-viewer с реальной подсветкой. Без бэкенда, всё клиентски.
- Импорт локальной папки (File System Access API + фолбэк), ноль сетевых запросов.
- `packages/parsers`: TexturePacker JSON (Hash + Array) и Pixi → норм. модель атласа
  `{ name, size, sprites[{name,x,y,w,h}], imageRef }`. Плюс одиночные PNG/WebP/JPG.
- `packages/analysis` (с юнит-тестами на эталонах):
  - **Occupancy** — сумма площадей фреймов / площадь атласа.
  - **Wasted regions** — через **грид-карту покрытия** (накрытые ячейки vs пустые → слить в прямоугольники).
  - **Format audit** — `canvas.toBlob('image/webp')` для быстрой цифры (lossless → wasm-libwebp позже).
  - **Dimensions** — флаги NPOT и абсолютного оверсайза.
- Анализ — в Web Worker; прогресс инкрементально.
- UI результатов: film-viewer на реальных данных — снимок + слой пустоты + находки + метрики
  (вес на диске, VRAM `Σ w×h×4`) + CTA-заглушка.

### Spike (параллельно, go/no-go по моату) — Render-probe POC
Загрузить атлас-PNG в offscreen PixiJS v8 (WebGL), достоверно вытащить draw calls и VRAM
(Σ по baseTexture `w×h×4`). Вывод go/no-go в `docs/render-probe-decision.md`.

### Что НЕ делать сейчас
Бэкенд/auth/биллинг (Phase 2); URL-краул и SDK/расширение (Phase 4); Spine, AVIF, реальную
перепаковку (позже); «after fix» с настоящим репаком (ценность фикса — числами и слоем пустоты,
не подделкой).

- **Токен-экономия:** держать `CLAUDE.md` сжатым; для крупного рефактора предлагать `/compact`;
  `@file`-ссылки вместо вставки больших файлов; тяжёлую логику — на старшую модель, рутину — на младшую.
- **Согласование vs действие:** библиотека, структура папок, схема БД, формат данных между
  пакетами — сперва короткое предложение. Реализация в согласованных рамках — действовать.

- **Тесты:** ядро анализа (`packages/analysis`, `parsers`) — обязательно с тестами на эталонах;
  пороги — в конфиге, не хардкодом.
- **Эталоны:** реальные/синтетические проблемные ассеты в `fixtures/sample-projects`.
- **Обновлять `CLAUDE.md`** при смене фазы/milestone и при появлении новых команд/соглашений.
