# Asset Doctor — каталог возможностей

Браузерный аудит ассетов для HTML5-игр (PixiJS/Phaser) + Pro-движок фикса, с opt-in
нативным бэкендом. Бесплатный диагноз работает на 100% в браузере (ассеты не покидают устройство);
Pro-фикс генерирует оптимизированный вывод; нативные-only операции выполняются на opt-in бэкенде (с согласием).

---

## 1. Диагноз — бесплатный аудит (в браузере, объективно, ≤10s)

- **PWA / офлайн (устанавливается)** — zero-dep service worker (без Workbox): прекэширует оболочку (index.html + entry JS/CSS + analyze-воркер) с версией = контент-хэш списка ⇒ новый деплой вытесняет старый SW и чистит устаревшие кэши (безопасная инвалидация). С ФИЗИЧЕСКИ выключенной сетью приложение грузится и прогоняет полный аудит — сильнейшее доказательство приватности (инв. 1), проверено e2e. Навигации network-first, хэшированные ассеты cache-first; тяжёлое (шрифты, wasm-кодеки, demo) — runtime-кэш. `manifest.webmanifest` + иконки для установки на рабочий стол.
- **Импорт целой папки** — File System Access API + фолбэк `webkitdirectory` + drag-drop; dir-aware группировка (manifest/spine + image) в нормализованную модель `Asset`.
- **Локальная история аудитов (P6)** — последний снапшот аудита хранится на имя папки в localStorage (ноль сети); повторный аудит под тем же именем показывает полосу «С прошлого аудита»: измеренные дельты headline-метрик (только ненулевые; disk и VRAM — отдельные строки) + счётчики added/resolved/changed по стабильному `Finding.id` — через то же diff-ядро, что `asset-doctor diff`. Копия честно хеджирует идентичность («папка с этим именем»), снапшот обрезан до полей диффа, кап 2 МБ пропускает сохранение вместо усечения (частичный снапшот дал бы неверный дифф).
- **Кнопка-демо «Посмотреть на примере»** — один клик на idle-экране запускает ПОЛНЫЙ реальный пайплайн на встроенном синтетическом сэмпле с документированными дефектами (протухший манифест ⇒ crit, недозаполненный атлас, solid-плиты, байт-дубликат) — instant wow без своей папки и без регистрации (инв. 4). Байты едут вместе с приложением lazy-чанком (1.8 КБ gzip), ноль fetch (инв. 1); результаты ИЗМЕРЕНЫ, не подстроены (инв. 3).
- **Парсеры** — TexturePacker JSON (Hash + Array), PixiJS atlas, одиночные PNG/WebP/JPG/AVIF (размеры из заголовка; AVIF — настоящий ISOBMFF box-walk meta→iprp→ipco→ispe, не байт-скан), Spine/libGDX `.atlas` (legacy + modern, multi-page по каноническому blank-line-контракту spine-ts, rotation/trim с полным `offsets`-переносом trim-смещения, страничный `scale:`) и BMFont `.fnt` во **всех трёх сериализациях — TEXT, XML и binary** (байт-в-байт `FntPage[]`; binary — дефолт BMFont.exe/libGDX). Pure и worker-safe.
- **Спрайтшит в первую очередь + честное сворачивание** — когда папка доминирована разрозненными loose-спрайтами (не спрайтшит), результаты ВЕДУТ заметной настраиваемой рекомендацией «Собрать спрайтшит» ([Собрать]→pack-план, [Настроить]→`#settings`), а вторичный per-image шум (только `format`+`dimensions-npot`) сворачивается в разворачиваемую группу — БЕЗ спама сотнями варнингов. Честно (инвариант 3): tally по ВСЕМ находкам до сворачивания, crit/folder никогда не сворачиваются, всё раскрывается в один клик с точным K, ничего не удалено/не выдумано; дефолт байт-в-байт.
- **Панель «Наибольший выигрыш» (с чего начать)** — обзорная панель после VerdictBar ранжирует находки, которые вернут БОЛЬШЕ всего, чтобы первый ответ был «с чего начать», без переключения сортировки леджера. Ранжирует `report.findings` по их СОБСТВЕННОЙ измеренной оценке в ДВА независимых списка в СВОЕЙ единице: топ-3 по `diskBytesSaved` и топ-3 по `vramBytesSaved`. Честность (инв. 3 и 5): НИЧЕГО не выдумывает (каждое число — `estimate` находки verbatim через `fmtBytes`); диск и VRAM — два раздельных списка в разных единицах, НИКОГДА не сводятся в один балл; находка входит в ось только при положительной измеренной экономии на ней (sparse/absent исключены, не фабрикованный 0); НЕ суммирует — элементы могут пересекаться, поэтому в панели НЕТ тотала (честный dedup-aware тотал — в budget-strip `potentialDiskSaved`). Детерминированный тайбрейк зеркалит triage. Клик по строке ставит ту же выборку, что клик по строке леджера (ассет ведёт плёнку, находка — оверлей/детали кабинета); панель монтируется только при ≥1 ранжируемом выигрыше (`hasWins`) ⇒ отчёт без находок с оценкой оставляет DOM байт-идентичным. e2e-гард: рендерится на demo-диагнозе + клик переводит плёнку. **Полный список — сортировка леджера `vramWin` (возврат VRAM):** близнец существующего `wastedDisk` (возврат диска) — finding-axis сорт по `estimate.vramBytesSaved`, DESC, sparse-в-конец; делает ранжируемыми находки только-по-VRAM (repack-opportunity/upscaled-source), которые раньше уходили в конец под любым ключом. Бейдж — зелёный возврат VRAM (role=saving), ОТЛИЧНЫЙ от нейтрального «VRAM (заявленный)» футпринта: пара «Потери на диске»/«Потери в VRAM» (возвраты) против «VRAM (заявленный)» (футпринт), никогда не смешаны (инв. 5). Метка ×10 локалей. **В общем экспорте отчёта:** та же секция «Наибольший выигрыш — с чего начать» ведёт MD и HTML (`asset-doctor audit --html` + веб-кнопки экспорта). Чтобы «наибольший выигрыш» означал одно и то же везде, чистое ядро `biggestWins` живёт в `@asset-doctor/budget` (один источник; apps/web — re-export-шим), поэтому CLI и веб печатают одинаковый рейтинг. Два раздельных списка (диск/VRAM), не суммируются, дисклоузеры исключены, без тотала; JSON НЕ тронут (байт-идентичен `audit --json`), CSV — сырые строки. **Дефолтный человеческий вывод CLI** (`asset-doctor audit <dir>`) тоже ведёт секцией «◆ Biggest wins — start here» (топ-3 диск + топ-3 VRAM через тот же `biggestWins`), так что impact-first-приоритизация есть на ВСЕХ поверхностях: веб-панель · сорт леджера · MD/HTML-отчёт · CLI (--md/--csv + дефолтный вывод) · CI-PR-комментарий (`diff --summary` футер «оставшийся выигрыш»).
- **Формат-сиблинги (одна картинка в разных форматах)** — `icon.png`/`icon.avif` (один stem, точные размеры, ≥2 mime, без res-токена) читаются как ОДИН логический ассет; VRAM считается один раз (формат-варианты идентичны в VRAM), а per-file совет «сконвертируй формат» на файле, чей рекомендованный формат уже есть у сиблинга, ДЕМОТИТСЯ (не удаляется). `icon_blue`/`icon_red` и res-тиры никогда не кластеризуются ложно.
- **Карта occupancy + wasted-region** — грид-карта покрытия по каждому атласу; подсвечивает пустое пространство (оверлей film-viewer). **Абсолютный флор severity** (`occupancy.minWastedBytes`, 256КБ): фракционная severity демотируется до info, когда (1−occ)·w·h·4 ниже флора — крошечный лист с ~118КБ пустоты больше не headline-crit рядом с мегабайтами на 2048²; растрата остаётся видимой (копия/params идентичны). Проверено на реальном корпусе (все 54 находки сохраняют severity).
- **Аудит размеров** — NPOT (гейт на реальном POT-padding-waste) + oversize (откалиброванный краевой порог).
- **Аудит форматов** — пробует реальный энкод AVIF/WebP и сообщает только об экономии, которую фактически измерил. **Абсолютный флор** (`formatSaving.minBytes`, 4КБ): высокий процент на крошечном файле — байтовый шум (35% от 2КБ-иконки ≈ 700 байт); флор гейтит измеренную экономию до срабатывания, подавление автоматически сжимает `potentialDiskSaved` и format-aggregate.
- **Content-class** — flat/alpha-арт получает lossless-вердикт (безопасно для инварианта 4, переиспользует дешёвый сэмпл).
- **Честность VRAM** — вес на диске ≠ VRAM: PNG 2048² = 16 MB на GPU (w·h·4), +33% с мипмапами; показывается явно.
- **VRAM с учётом мипмапов** — учёт base + ceiling (`vramBytesMipmapped`).
- **Folder rules** — duplicate-exact (SHA-256), duplicate-similar (dHash, flat-guarded **+ цветовой гард**: dHash строится из знаков градиента лумы ⇒ цветослеп, рекраск-двойники формы хэшируются идентично; альфа-взвешенный средний цвет из того же 9×8-сэмпла отвергает пары с |Δ|>`maxMeanColorDelta` на любом канале — «переиспользуй один» больше не советуется намеренно разным рекраскам; **кластеризация complete-linkage** — кандидат входит в группу лишь когда он в пределах обоих порогов от КАЖДОГО члена, а не только якоря, ⇒ отчётный набор честно удовлетворяет заявленной границе «dHash ≤ N бит» попарно, без транзитивного обхода через неравенство треугольника), should-atlas, atlas-merge, integrity (отсутствующее изображение), format-aggregate.
- **Shared-page merge** — атласы, разрешающиеся в одно изображение, объединяются + считаются один раз (убивает фантомный двойной учёт VRAM).
- **Variant-aware VRAM** — кластеризует варианты `name_res[_fmt]`; один логический ассет грузится один раз → `loadedVramBytes` (worst-case tier). `hasResolutionToken` заглядывает ПОД трейлинг-формат-суффикс (`hero_1080p_webp`), так что `<имя>_<res>_<fmt>` файлы кластеризуются как ОДИН логический ассет с png-лестницей — раньше они бакетились отдельно и заявленный (DECLARED) VRAM удваивал верхний tier (~2× over-claim на реальном корпусе). Честность инв. 3/5: один tier резидентен на девайс.
- **Фрагментация атласа** — оценка разброса используемого vs свободного пространства.
- **Dry-run repack (`repack-opportunity`)** — диагноз ПРОГОНЯЕТ настоящий MaxRects-упаковщик фикса (`pack.ts`, дефолты фикса: padding 2, maxSize 4096; **зеркалит rotation-гейт фикса** — twice-pack, ротированные бины при строго меньшем VRAM, rotation-packing v2) по фреймам каждого атласа и сообщает ИЗМЕРЕННЫЙ достижимый лист («умещается в 512×512 — освобождает 3.0 MB VRAM (измерено)») — по построению ровно то, что даст plain-репак фикса (консервативный пол: trim/дедуп/полигоны ужмут сильнее). Честность: `vramBytesSaved` — из реальной упаковки, никогда не модель площади; диск не заявляется; гейты declared==real / ≥2 спрайтов / однобинный результат / пол 256 КБ / bmfont исключён; warn ⟺ VRAM ополовинен (структурный сброс POT-тира). Deps-gated: CLI/headless без сима ⇒ тишина, байт-в-байт.
- **Детектор сплошной заливки** — одноцветные изображения, держащие VRAM ради одного цвета. Дешёвый 9×8-сэмпл — только КАНДИДАТ; вердикт ПОДТВЕРЖДАЕТСЯ на ПОЛНОМ разрешении (иначе мелкая непрозрачная деталь ≤~62×62 в 2048²-поле «усреднялась» бы и фабриковала полную VRAM-экономию — нарушение инв. 3). Подтверждение строго сужает solid-множество (ни одна картинка не становится solid заново); переиспользует opaque-scan буфер. Полноразрешающий скан скалярно-развёрнут по каналам (~40% быстрее — держит per-image стоимость под бюджетом «≤10с», инв. 4; поведение байт-в-байт, запинено граничными tol-тестами).
- **Детектор доказуемого апскейла (`upscaled-source`)** — текстура, точечно (nearest) растянутая из меньшего источника, не несёт деталей в своём размере, но платит полный w·h·4 VRAM. `blockUpscaleDepth` (`perceptual.ts`) — это ДОКАЗАТЕЛЬСТВО, а не эвристика: максимальное k, при котором каждый выровненный по сетке блок 2×2 на каждом из k уровней халвинга — один константный RGBA (альфа включена) ⇒ изображение является k-уровневым целочисленным nearest-2×-апскейлом источника (w>>k)×(h>>k), восстанавливаемого без потерь. Порога срабатывания нет, ложных срабатываний не бывает (один отличающийся пиксель обрывает спуск); первый full-res-проход short-circuit-ит на первом неконстантном блоке (детализированная картинка выходит мгновенно — инв. 4), считается на ТОМ ЖЕ декоде, что opaque/solid-сканы. Скан сравнивает пиксель как один uint32 (все 4 байта разом; равенство не зависит от порядка байт) на типизированном getImageData-буфере ⇒ ~3.2× быстрее в худшем случае (41.7→13.2 мс на 2048²; держит per-image стоимость под «≤10с», инв. 4; байтовый fallback для `number[]`, поведение байт-в-байт). Находка несёт `vramBytesSaved` под ЯВНЫМ проверяемым условием (поставить восстановленный источник; прецедент npot), **только VRAM — никакого diskBytesSaved** (источник не перекодировали, инв. 5) и без суммирования в заголовочные тоталы. Де-оверлап с solid-fill; loose-only; browser-only (CLI не срабатывает). Гладкие (bilinear) апскейлы НЕ ловятся — это отдельный band-limited случай.
- **Детектор wasted-alpha** — полностью непрозрачные изображения, несущие альфа-канал (полнокадровый проход на непрозрачность, short-circuit, безопасно для instant-wow); экономия только на диске. Копия честно атрибутирует дельту НЕПРОЗРАЧНОМУ ПЕРЕКОДИРОВАНИЮ (удалённый канал + пережатие canvas-кодировщиком, показан измеренный opaqueBytes), а не «стоимости канала» в отдельности (UI-honesty).
- **Детектор frame-redundancy** — байт-в-байт дубликаты кадров *внутри* атласа (per-region SHA, flat-guarded, instant-wow капы); точная wasted atlas-area/VRAM.
- **Детектор loose-in-atlas (N4)** — loose-картинка, чья ПОЛНОРАЗМЕРНАЯ декодированная RGBA байт-идентична региону кадра атласа ⇒ тот же спрайт отгружен ДВАЖДЫ (loose + упакован в атлас) — реальная ошибка сборки, невидимая сегодня (`duplicate-exact` = loose-vs-loose по хэшу ФАЙЛА; `cross-atlas-redundancy` = кадр-vs-кадр; ни одно не сравнивает loose-пиксели с кадром). PROOF по SHA декодированной RGBA (та же основа, что у хэшей регионов кадров ⇒ прямо сравнимы), flat-guarded, только UNtrimmed кадры матчатся (proof недо-заявляет, ноль ложных срабатываний). Честно (инв. 3/5): severity warn + хедж «какая копия используется — зависит от игры»; ТОЧНАЯ экономия (disk-байты loose + w·h·4 VRAM, раздельные поля) — на находке, НЕ в headline `potentialDiskSaved` (консервативно). Дважды deps-gated (нужны И pixelHash-фичи, И frameHashes) ⇒ CLI байт-идентичен; per-sprite drill-down показывает disk-байты на редундантную копию.
- **Детектор strippable-metadata** — чистый header-only байт-проход (без декода), суммирующий ТОЧНОЕ число вырезаемых вспомогательных байтов (PNG `iCCP/eXIf/tEXt/iTXt/zTXt/tIME`, JPEG `APP1..15`+`COM`, WebP `EXIF/XMP/ICCP`; чанки, влияющие на рендер, исключены); экономия **только на диске** (GPU всё равно декодирует в RGBA8888), MAX-де-оверлап против находок format/wasted-alpha, называет существующий фикс oxipng/re-encode. Консервативная истинная нижняя граница (никогда не завышает).
- **ICC-честность (`icc-non-srgb`)** — встроенный ICC-профиль срезается бесплатно, ТОЛЬКО если он sRGB (sRGB — дефолт веба/GPU, его удаление ничего не меняет). Не-sRGB профиль (Display P3 / Adobe RGB) **несущий**: его удаление молча сдвигает цвета. Чистый header-only зонд `iccProfileInfo` (`packages/parsers/src/icc.ts`, без декода — инв. 1) доказывает sRGB через чанк `sRGB` / имя профиля iCCP `/srgb/i` (сжатый профиль никогда не инфлейтится) либо через тег `desc` сырого ICC у JPEG `APP2 ICC_PROFILE` и WebP `ICCP` (ICC v2 `desc` + v4 `mluc`). Нет доказательства ⇒ байты **ИСКЛЮЧАЮТСЯ** из `strippableMetadataBytes` (консервативная истинная нижняя граница), Pro-фикс **сохраняет** чанк (инъектированное решение `keepIcc`; у WebP при этом сохраняется флаг ICC в VP8X), а находка **`icc-non-srgb` (info) раскрывает это БЕЗ какой-либо оценки** (ни диск, ни VRAM — прецедент bleeding/dimension-mismatch). Байтовые счётчики зонда зеркалят strippable-обходы, а тест-якорь `removed === strippableMetadataBytes` пинит lock-step детектора и фикса.
- **Раскрытие внутренней прозрачности (fill-rate)** — полностью прозрачные пиксели ВНУТРИ непрозрачных границ спрайта (кольца, искры, диагональные клинки) растеризуются на каждом дроу — растрата fill-rate/overdraw, которую прямоугольная упаковка не убирает. `alphaShape` (чистая, тот же full-res буфер — ноль лишнего декода): тесный bbox альфы>0 + точный счёт альфа===0 внутри; прозрачные ПОЛЯ намеренно вне bbox (территория trim, не «дыры»). Fill-rate байтами не измерить ⇒ **info без оценки**; fix-копия указывает на отгруженный полигональный упаковщик (mesh-режим пропускает прозрачные пиксели). Loose-only, browser-only.
- **Раскрытие бинарной альфы** — каждый альфа-байт строго 0/255 ⇒ 8-битный канал доказуемо хранит 1 бит (territория palette/PNG8, BC1 punch-through, KTX2 alpha-mask). Точный факт из того же скана; 1-битный реэнкод в браузере не измерить ⇒ **info без оценки**. Де-оверлапы: полностью непрозрачное — wasted-alpha, solid — solid-fill. Loose-only, browser-only.
- **Раскрытие выравнивания GPU-блоков (`gpu-compression-alignment`)** — текстуры с шириной/высотой не кратной 4 не ложатся чисто на 4×4-блоки блочно-сжатых GPU-форматов (путь KTX2 → BC/ASTC отгруженного opt-in бэкенда): транскодер паддит или откатывается на части таргетов. Header-only (только распарсенный размер — ноль декода), считает и loose, и страницы атласов. Честность: только ФАКТ выравнивания — никогда «нельзя сжать» (KTX2 паддит внутренне) и никогда VRAM-предсказание (реальный футпринт меряет on-device KTX2-probe). Folder-level (одна info-находка при ≥2, без оценки); browser-only (CLI байт-идентичен).
- **Раскрытие избыточного gutter (`excessive-gutter`)** — обратка bleeding: медианный зазор кадров до ближайшего упакованного соседа ≥ порога = систематически переупакованные поля, тратящие площадь листа на воздух. Чистая целочисленная геометрия по `atlas.sprites` (ноль декода): ближайший правый/нижний сосед через сортировку, нижняя медиана (детерминированно); касающиеся кадры дают 0 и тянут медиану вниз ⇒ плотные листы не срабатывают. **info без оценки** — сколько вернёт плотный репак, зависит от раскладки; отгруженный Pro-репак меряет реальное до/после в чеке. Browser-only (CLI байт-идентичен).
- **Раскрытие premultiplied-alpha halo** — спрайты, чьи мягкие края имеют «premultiplied-форму» (сохранённый RGB спадает к чёрному вместе с альфой вместо цвета непрозрачной части), дадут тёмный ореол, ЕСЛИ загрузчик смешивает их как straight-альфу. Метрика `premultipliedEdgeShape` (чистая, на том же full-res буфере, что opaque/solid/upscale — ноль лишнего декода): подразумеваемая подложка m = (L_P − L_Q·α)/(1−α) на настоящих anti-aliasing переходных пикселях у ярких непрозрачных соседей; гейты убивают ловушки (тёмные контуры, глоу без ядра, жёсткие вырезы). **Неустранимый предел честности:** premultiplied-экспорт байт-идентичен straight-арту на чёрной подложке ⇒ это УСЛОВНОЕ РАСКРЫТИЕ (всегда info, БЕЗ какой-либо оценки, «мы измеряем пиксели, а не ваш режим смешивания»), закреплено байт-идентичность-тестом. Folder-level: одна находка на папку со списком спрайтов (≥2, прецедент format-aggregate) ⇒ шум ограничен; browser-only, loose-only.
- **Раскрытие мёртвых Spine-регионов (`spine-unreferenced-regions`)** — регионы атласа, на которые не ссылается ни один аттачмент ни одного СПАРЕННОГО скелета (.json из той же папки; объединение по всем скинам — анимации именуют плейсхолдеры скинов, поэтому этого достаточно), статически недостижимы, но поставляются и загружаются со страницей. Три гарда честности: sequence-префиксы (кадры секвенций 4.1+ не флагаются), подавление при бинарном `.skel` в папке (нечитаемый скелет может ссылаться на что угодно) и **pairing-trust гейт** (чужой скелет матчит ~0 имён и структурно не может дать «всё мёртвое»). Условное раскрытие: всегда info, **БЕЗ оценки** (числа в params), хедж на runtime `setAttachment`; overlay `dead-region` — реальные frame-ректы. Консервативный ридер скелета: незнакомая форма ⇒ null ⇒ правило молчит. Browser-only в v1 (CLI без привязок).
- **Детектор texture-bleeding** — чистая целочисленная смежность кадров (без декода): помечает пары кадров атласа, упакованные с 0px gutter (общая грань + перпендикулярное перекрытие; угловые касания и rotated/aliased кадры исключены), которые могут давать 1px-швы при linear/mipmap-сэмплинге. Это находка **корректности** БЕЗ экономии (edge-extrude может увеличить лист — инвариант 5), с условной честной оговоркой; зажигает бирюзовый оверлей `bleeding` и указывает на существующий фикс edge-extrude.
- **Детектор declared-vs-real dimension-mismatch** — всегда включённый статический собрат метки render-probe: сравнивает объявленный в манифесте `meta.size` (Spine page `size:`) с РЕАЛЬНЫМ декодированным заголовком пикселей (без декода), за пределами небольшого абсолютного допуска. Direction-aware (real<declared с кадром за реальной гранью = crit; в пределах границ = warn; real>declared = info). Это находка **корректности** БЕЗ оценки — приводит два измерения (declared vs real), никогда не заявка на экономию от фикса. **VRAM атласа считается по РЕАЛЬНОЙ декодированной странице** (`image.size` — текстура, которую грузит GPU), как и loose-путь, а не по заявленному `atlas.size`: на здоровом атласе они равны (байт-в-байт), на битом манифесте заявленный размер фабриковал бы футпринт, который GPU не аллоцирует (инв. 5). Геометрия (occupancy/wasted-regions/oversize/npot) остаётся на заявленном `atlas.size` — координатном пространстве размещения фреймов.
- **Surfacing неразобранных файлов** — файлы, выглядящие как манифест, но не поддающиеся парсингу, показываются честно (никогда не отбрасываются молча) + усиленные парсеры кадров/Spine (отвергают neg/zero/OOB rect; Spine `numsRaw` per-region recovery). **Ротированные кадры TexturePacker/Pixi** хранятся КАК РАЗМЕЩЕНЫ (w/h свапнуты, как в контракте core и Spine-парсере) — чинит overlay пустоты/region-dedup/OOB на реальных ротированных атласах; parse↔emit точное тождество (эмит свапает обратно в TP-форму). **Гарды позитивности размеров** — `readSize` (TP/Pixi) и Spine `size`/`bounds` отвергают не только нефинитные, но и `≤0` значения ⇒ битый `{0,0}`/негативный `meta.size` не отвергает целиком хороший атлас (проваливается на реальный размер картинки), а непозитивный Spine-регион дропается честно в `malformedRegions` (не выдуманный размер).
- **Честная оценка VRAM у atlas-merge** — экономия от мерджа считается по консервативной нижней границе: `packEfficiency` (0.8) дисконтирует полезную ёмкость листа ⇒ `vramBytesSaved` НИКОГДА не завышается (раньше допускалась 100%-упаковка = верхняя граница). **Отказ на mixed-resolution мердже** — atlas-merge группирует по occupancy, поэтому может выбрать атласы с РАЗНЫМ `meta.scale` (0.5×-вариант + 1×); слить их на один лист с одним `meta.scale` значило бы рендерить чужие масштабы неверного размера, поэтому воркер ОТКАЗЫВАЕТ такой группе (честный скип, атласы уходят нетронутыми) через чистый `atlasesShareScale` (все-1× разделяют scale ⇒ обычный мердж не затронут, ложных срабатываний нет).
- **Экспорт/шаринг отчёта аудита (JSON · Markdown · CSV · HTML · копировать)** — на экране результатов группа «Экспорт отчёта»: копия Markdown-таблицы находок в буфер + скачивание JSON/MD/CSV/HTML, всё собрано В БРАУЗЕРЕ из уже измеренного отчёта (ноль сети — инв. 1). JSON — `@asset-doctor/budget` `toJSON` ВЕРБАТИМ ⇒ байт-в-байт как `asset-doctor audit --json` для той же папки (кросс-инструментальный diff, ноль дрейфа); MD/CSV — целевые сериализаторы находок с ДЕТЕРМИНИРОВАННЫМ порядком (crit→warn→info→ok, тай-брейк по assetRef) для чистых diff'ов; **HTML** — самодостаточная стилизованная страница (inline-`<style>`, system-font, БЕЗ `<script>`/`<img>`/`<link>`/url()/удалённых ссылок ⇒ ноль fetchable-ресурсов; **injection-safe** — `escapeHtml` на каждой интерполяции, доказано на адверсариальных именах ассетов), которую нетехнический коллега просто откроет в браузере. Честность: только форматирует/упорядочивает измеренное (`fmtBytes`/`sortFindings`), ничего не считает; disk-saved и vram-saved — ОТДЕЛЬНЫЕ колонки, никогда не суммируются (инв. 5); «(est.)» в заголовках; disk≠VRAM-заметка в MD/HTML. Чистый Node-тестируемый `report-export.ts`.

## 2. Render-probe и рантайм-профайлер (moat)

- **Render-probe** — загружает атлас в offscreen PixiJS v8 WebGL, инструментирует GL-контекст и считывает **измеренные** draw calls + VRAM (Σ baseTexture w·h·4).
- **Runtime profiler SDK** — патчит `getContext` + оборачивает RAF; per-frame draw calls, избыточные binds, uploads/shader-compiles (hitches), live textures, VRAM, fps. **Честность измерения (N2-аудит):** warmup якорится к СТАРТУ сессии (абсолютный `totalFrames`), поэтому бесконечная сессия HUD не отбрасывает вечно steady-state gameplay-кадры как «warmup» (иначе недосчёт uploads/hitches); VRAM блок-сжатых текстур — per-level residency (`compressedTexImage2D` ЗАМЕНЯЕТ уровень, sub-image добавляет НОЛЬ), поэтому пере-загрузка/стрим сжатой текстуры не раздувает `vramBytes` (инв. 5).
- **Захват blend-конфигурации (P8)** — инструмент патчит `blendFunc`/`blendFuncSeparate`/`pixelStorei` и ИЗМЕРЯЕТ реальный alpha-blend движка: premultiplied (srcRGB=ONE) / straight-alpha (srcRGB=SRC_ALPHA) / mixed / upload-premultiply. На `RuntimeReport.blend`, в HUD расширения (`blendModeLabel`) и в экспорте сессии — фактический GL-readout, не вердикт. Это измеренный контрагент для условной находки premultiplied-alpha — теперь потреблён в correlate R6 (ниже).
- **MV3 Chrome-расширение** — инжектит профайлер в живую игру (MAIN world) + on-page HUD + «load folder & correlate» в оверлее. **Оверлей считает пиксельные фичи** (расшаренный `@asset-doctor/pixel`: тот же per-image декод, что у веб-воркера, по каждому loose PNG/WebP) ⇒ feature-rich static: premultiplied-alpha и прочие пиксельные находки доходят до correlate прямо в странице (закрыта «featureless-static дыра»). **Статические находки видны в оверлее (N3):** `lastStatic.findings` рендерятся через ТОТ ЖЕ локализованный `renderFinding`, что и веб — severity-карточки (title + fix) в скроллящейся секции; так пиксельные находки (solid/opaque/upscaled-source/premultiplied/interior/binary/duplicate) видны, а не только скармливаются correlate. **Хэши регионов кадров атласа** тоже считаются в странице (расшаренный `extractFrameRegions` + SHA-256, та же основа, что у loose-pixelHash) ⇒ findings-отношения атласа — cross-atlas-redundancy, frame-redundancy, loose-in-atlas — тоже срабатывают и отображаются: полный паритет статического аудита с вебом (минус format/wasted-alpha, которым нужны canvas-энкодеры).
- **Слой correlate** — `correlate(static, runtime)` → один вердикт (статическая фрагментация × живые draw calls/binds, резидентность VRAM, upload/shader hitches, избыточный state). **R6 premultiplied × ИЗМЕРЕННЫЙ blend (N1):** статическая находка premultiplied-alpha хеджирует по режиму смешивания, P8-захват его РЕЗОЛВИТ — **halo** (измерен straight-alpha, warn: тёмные края просвечивают каймой) / **safe** (измерен premultiplied, info: согласовано) / **inconclusive** (оба/только-upload, info: цитирует измеренный mode-токен). Честность: static-доказательство хранит неустранимый хедж «измерена ФОРМА края, не blend mode»; R6 резолвит только режим смешивания, не авторинг, и не срабатывает без измеренного сигнала. Проверено ВЖИВУЮ (`ext-premult-run.mjs`: реальное расширение на straight-alpha WebGL-странице + premultiplied-shaped фикстура → halo-вердикт в оверлее). 14 i18n-ключей × 10 локалей.
- **Рантайм A/B двух живых сессий (`#compare`)** — грузишь запись живой сессии игры ДО фикса и ПОСЛЕ (локально через `FileReader`, ни один ассет не покидает устройство) и видишь дельты по метрикам. **Агрегат-к-агрегату** (в отличие от прибитого V3 — пер-текстурная атрибуция невозможна): вся честность в сопоставимости нагрузки, аттестуемой ПОЛЬЗОВАТЕЛЕМ (та же сцена / то же устройство), никогда не допущение. Каждая метрика несёт КЛАСС чувствительности — per-frame (честно только под «та же сцена»), state (растровый VRAM — одна база w·h·4 с обеих сторон), session-total (гейт по длительности `maxDurationSkewPct`), device/timing (сравнимо ТОЛЬКО под «то же устройство»). **Честность (инв. 3):** гейт `minFrames` 120 (иначе `too-short` — все дельта-вердикты умирают, сырые значения показываются: ничего не прячем); строки device/timing **скрыты целиком** без аттестации устройства; несопоставимые строки — сырые значения + классовый хедж, НИКОГДА причинность; дельта — знаковая величина без «хорошо/плохо»-цвета. Ядро (`compareRuntimeReports`) и view-model (`compare-view`) — чистые, Node-тестируемые; JSX — тонкий рендерер. i18n ×10; динамические ключи вердикта/метрики/хеджа дрейф-гардятся против вывода чистой модели. **Строка «сжатый VRAM (измерено)»** — device-измеренная блок-сжатая часть `vramBytes` (Σ реальных байт `compressedTexImage2D` по всем WebGL-перегрузкам, вкл. мипы; подмножество total-VRAM, помечено «измерено» против «заявлено» у растрового w·h·4). Появляется только когда ОБЕ сессии её записали (старый экспорт ⇒ `undefined` ≠ измеренный 0 ⇒ строка опускается, ничего не фабрикуется); показывается даже при 0 → 0 — это честно вскрывает KTX2-сборку, откатившуюся в растр на устройстве.
- **Probe-в-вердикт** — диагноз может показать измеренный GPU-футпринт (declared vs measured). Сравнение like-for-like: измеренному (Σ по РЕАЛЬНО зондированным атласам) противопоставляется НЕ whole-folder-дедуплицированный заголовок, а `declaredVramBytes` по ТОМ ЖЕ набору зондированных атласов + число зондированных; тултип честно объясняет разницу ОБЛАСТЕЙ (не «до/после»).

## 3. Pro-движок фикса (браузер — генерирует оптимизированный вывод)

- **Atlas repack** — собственный MaxRects/BSSF, smallest-area POT bin, rotation/padding/spill; более плотный лист, переэмитированный манифест (drop-in). **Rotation-packing v2 (rect-путь):** упаковщик может класть спрайт повёрнутым на 90°, чтобы уместить landscape в portrait-щель. MEASURED-гейт (twice-pack): ротированные бины берутся ТОЛЬКО когда строго меньше по Σ w·h·4 VRAM ⇒ ротация только при реальном уменьшении. Эмитится `rotated:true` + un-rotated frame в манифесте (лоадер Pixi/TP восстанавливает), compose рисует регион повёрнутым на 90° CW — направление ПРОВЕРЕНО попиксельно против первопринципного CW-поворота (e2e-гард). Scope: только rect-репак untrimmed source-неротированных спрайтов (loose-pack + polygon вне scope). Deps: dry-run `repack-opportunity` sim остаётся БЕЗ поворота (консервативный пол). **Чек фикса сообщает «повернули N спрайтов на 90°»** (i18n-плюрал ×10): воркер аккумулирует `RepackResult.rotatedFrames` по обоим путям репака в `FixReceipt.rotatedFrames`, App.tsx рисует строку ТОЛЬКО при >0 — прозрачность для автора кастомного загрузчика (нужно чтить `rotated:true`-кадры). Честность (инв. 5): VRAM/диск-выигрыш УЖЕ внутри `vramBytesBefore/After`, счётчик информативный, не отдельная экономия; 0/absent ⇒ чек байт-идентичен.
- **Binary polygon packer** — nesting по occupancy через bitmap-mask (trace alpha → conservative RDP → ear-clip → bitmap nesting + mesh-clip compose); TexturePacker-совместимый mesh-манифест (`vertices/verticesUV/triangles`); честный VRAM-гейт, rect-фолбэк; trim по content-extent (без пустого низа).
- **Resize** — даунскейл оверсайз loose-изображений + атласов (кадры clamped); drop-in.
- **Transcode** — WebP/PNG (нативный `convertToBlob`) + AVIF + lossless-WebP + oxipng (через `@jsquash`, честный фолбэк).
- **Spine repack** — более плотный single-page Spine-лист + переэмитированный `.atlas`. **Сохраняет `filter:`/`repeat:` страницы дословно** (Nearest для пиксель-арта, tiling-wrap) — раньше эмит захардкоживал `Linear,Linear`/`none`, молча замыливая пиксель-арт-атлас при репаке; теперь GPU-хинты сэмплера переносятся из источника (модель `Atlas.filter?`/`repeat?`), откат на дефолт только при отсутствии ⇒ обычный атлас байт-идентичен. **ОТКАЗ на premultiplied (`pma: true`) атласах** — canvas-2D-рекомпозиция не байт-лосслесс для premultiplied-пикселей (ИЗМЕРЕНО: alpha≤16 схлопывается к 0, до Δ8 — `tools/verify/pma-roundtrip-measure.mjs`), поэтому репак/тиринг pma-атласа ПРОПУСКАЕТСЯ с честной причиной (оригинал уходит нетронутым, `pma` цел), а `emitSpineAtlasText` ре-эмитит `pma: true` на verbatim-путях, чтобы флаг не терялся молча (иначе лоадер читает premultiplied как straight ⇒ пересвет/каёмки). **Сохраняет `meta.scale`** — 0.5×-вариант разрешения (`meta.scale`/Spine `scale:`) переносится через репак (репак держит пиксели 1:1 ⇒ фактор не меняется); раньше репак ронял его ⇒ лоадер читал 0.5×-атлас как 1× и рендерил спрайты вдвое больше. **Сохраняет карту `animations`** (TexturePacker/Pixi, имя-кадра→порядок) при одно-источниковой одно-листовой перепаковке — репак name-стабилен (все имена кадров сохраняются), так что ссылки валидны (как у `scaleAtlas`); раньше дропал «by construction» ⇒ терял анимации; merge/spill продолжают дропать (документировано).
- **Aggressive dedup** — модель owner/consumer (pools/skin, lazy-aware), отбрасывает exact + near-дубликаты, перепривязка ссылок.
- **Edge-extrude (bleed)** — симметричный gutter для устранения bilinear-швов.
- **Per-image выбор измеренного лучшего формата** — переносит в фикс измеренного в диагнозе победителя по наименьшему энкоду.
- **Opaque-encode** — переэнкод wasted-alpha изображений без альфы (только диск; guard keep-original-on-size-loss).
- **Lossless-strip метаданных** (`strip` FixOp) — исполнитель детектора strippable-metadata: чистый `stripImageMetadata` вырезает ТОЧНО те ancillary-чанки (ICC/EXIF/XMP + PNG text/tIME), что считает `strippableMetadataBytes`, БЕЗ декода/реэнкода ⇒ пиксели и формат байт-в-байт идентичны (drop-in, сильнее canvas-реэнкода — без потери качества и без смены формата). Кросс-чек тест: `removed >= strippableMetadataBytes` (===  для форматов без паддинга) ⇒ фикс убирает РОВНО измеренное. **Только диск** (VRAM не меняется — инв. 5): вклад в vramSaved = 0. Эмитится только для ref, который НЕ перекодируется другим op (де-оверлап с transcode/repack/resize/pack/tier + исключение dedup-владельцев) ⇒ единственный способ вернуть эту экономию, когда файл сохраняет исходный формат; дефолт OFF ⇒ байт-в-байт. First-class OpKind (тэлли/preview/receipt); тумблер «Strip metadata (lossless)» в Настройках, config v2.
- **Selective fix** — выбор, какие находки фиксить (masked preview).
- **Dry-run превью плана** — увидеть план перед скачиванием.
- **Receipt + per-file манифест изменений** — disk/VRAM before→after, трейл операций, честные предупреждения «references changed». **Жёсткая VRAM-экономия чека — консервативная истинная граница**: near-duplicate bare-drop (без репойнта) НЕ сворачивает нереализованный `w·h·4` в жёсткую строку — он вынесен ОТДЕЛЬНОЙ верхней границей (контингентно на ручной репойнт), как у exact-dup пути. **Dry-run превью кредитует РЕАЛЬНЫЙ таргет** (не strict-smaller bestMime): при `bestFormatPerImage` OFF превью не завышает disk-экономию, а defer'ит (fail-safe) при codec-mismatch ⇒ консервативно совпадает с реальным прогоном.
- **Engine-aware гид по миграции лоадера** — copy-paste сниппеты Pixi/Phaser, когда фикс переписывает вызовы лоадера (включая сниппет KTX2 `import 'pixi.js/ktx2'`). Spine (Phaser) эмитит корректный `this.load.spineAtlas(key, url)` с реальным `.atlas` (без выдуманной ext-swap `.png`-страницы).
- **Before/after FilmViewer sheet-diff** — две side-by-side рентген-плёнки на каждый перепакованный лист + оверлей пустого пространства (визуальное доказательство, не экономия).
- **Render-probe произведённого фикса** — измеренные before→after draw calls + декодированный VRAM на лист (3-й собрат probe).
- **correlateFix** — превращает измеренный probe фикса в локализованный вердикт доктора.
- **Собственный zero-dep store-only ZIP** (CRC32, UTF-8 flag, overflow guards). Вывод скачивается как `optimized-folder.zip`.

## 4. AssetPack-дуга / сборщик ассетов — config-driven пайплайн экспорта

> **Сценарий «сырьё → конфиг → готовая папка»** (паритет с asset-builder, всё в браузере): загрузить папку сырых ассетов → настроить профиль (форматы, степени сжатия, качество, **субсемплинг**, уровни скейла с **выбором суффиксов**) → скачать `optimized-folder.zip` ТОЙ ЖЕ структуры с готовыми спрайтшитами / Spine-`.atlas` / Pixi-JSON. Конфиг можно сохранить/загрузить как версионированный JSON.

- **Отдельная страница настроек (`#settings`)** — все ручки оптимизации собраны в ОДИН `BuildSettings` на отдельной hash-роут-странице (ссылка «Настройки» в шапке, результаты анализа переживают переход), карточками-секциями как у asset-builder: Форматы · Разрешения · Упаковка · Мипмапы · Правила · Вывод · Бэкенд · Конфиг. `settingsDefaults()` воспроизводит прежнее поведение байт-в-байт. Конфиг **v2** save/load покрывает всю поверхность (v1-файлы мигрируют); backend-тоглы и per-run consent НЕ сериализуются.
- **Форматы страниц атласа honor профиль** — перепакованные/смерженные/собранные листы теперь кодируются в выбранный формат (webp/avif/quality/субсемплинг), а не жёстко lossless-WebP/PNG; при профиле OFF repack/merge держит lossless-WebP (геометрический lossless-фикс), pack — legacy-таргет ⇒ дефолт байт-в-байт. Spine-страницы: политика `png` (безопасно, дефолт) / `profile` (+честная заметка о рантайм-декоде).
- **Честная секция мипмапов** — растровые PNG/WebP/AVIF физически НЕ хранят мип-уровни (GPU генерит при загрузке, ≈+33% VRAM — это меряет находка `mipmap-cost`); opt-in KTX2-бэкенд печёт настоящие мипы, extrude лечит швы. UI даёт копирайт + существующие ручки, НЕ генерирует пиксели (инвариант 3).
- **Config-driven профиль экспорта** — произвольные разрешения × форматы (png/webp/avif, lossless+lossy) × per-format компрессия (quality/near/effort); + глобальные encode-ручки (effort/scaleAwareQuality/pngRecompressLevel) и **пикер AVIF-субсемплинга (4:4:4/4:2:2/4:2:0)** в UI, с fail-closed валидацией. Заменяет фиксированную 3-tier лестницу. Аддитивно (off ⇒ байт-в-байт).
- **Сохранение структуры папок** — вывод зеркалит входное дерево сквозняком (нетронутые файлы проходят по своему пути; трансформированные меняют только базовое имя/расширение).
- **Принудительный формат на предсобранных атласах** — при single-format профиле КАЖДЫЙ подходящий атлас конвертируется в выбранный формат (а не только заработавшие находку), с keep-original-on-size-loss; больше нет «смешанной» папки.
- **Пользовательские суффиксы уровней скейла** — безопасный charset (буквы/цифры/`_`/`-`, не имя формата); resolution-суффиксы по-прежнему кластеризуются на ре-ингесте, кастомные показываются как отдельные ассеты (консервативно).
- **Импорт/экспорт build-конфига** — сохранить/загрузить весь профиль + глобальные ручки как версионированный JSON; fail-closed через тот же `validateProfile`; backend-тоглы и consent НЕ сохраняются (per-run), без localStorage.
- **Первоклассный аффорданс «Оптимизировать эту папку»** — заголовок + якорь на экране результатов, раскрывающий панель экспорта (обнаруживаемость; instant-wow-диагноз не задет).
- **Per-folder/prefix оверрайды** — матч ассета по пути и оверрайд forматов/quality/lossless/AVIF-4:4:4 (например, `fonts → 4:4:4`); паритет с asset-builder в честном браузерном подмножестве.
- **Per-folder/prefix оверрайды** — матч ассета по пути и оверрайд forматов/quality/lossless/AVIF-4:4:4 (например, `fonts → 4:4:4`); паритет с asset-builder в честном браузерном подмножестве.
- **Multi-resolution scale-tiers** — `_1080p/_720p/_540p` (теперь config-driven) с честным disk-only fan-out.
- **Эмиттер PixiJS manifest.json** — настоящий Pixi v8 `AssetsManifest`, чтобы весь оптимизированный вывод грузился одним `Assets.init({ manifest })` (одна alias-suffixed запись на каждый tier разрешения; листы указывают на сайдкар `.json`/`.atlas`).
- **Content-hash cache-busting** — добавляет content-хеш к эмитируемым именам файлов, прокинутый через atlas `meta.image`, строку Spine `.atlas`, манифест Pixi, dedup-consumer изображения и строки миграции лоадера.
- **Упаковка loose-ассетов в спрайтшиты** — с нуля: статический TexturePacker JSON + корректная композиция Spine `.atlas`, multi-page spill.
- **Multipack round-trip safety** — `meta.related_multi_packs` TexturePacker (связка sibling-`.json`, которую Pixi v8 авто-загружает) проносится дословно через байт-стабильный passthrough/resize re-emit и честно вырезается (со skip-нотой) на каждом пути, переименовывающем siblings (tier-суффиксы, KTX2, content-hashed имена) — так что page-0 мультипака продолжает грузить страницы 1+ вместо их молчаливого отбрасывания.
- **Animation-map round-trip** — top-level карта `animations` спрайтшита (group → упорядоченный список имён кадров = порядок воспроизведения, из которого строится `AnimatedSprite`) проносится дословно (никогда не сортируется) через каждый Pro re-emit; поскольку она ссылается на КЛЮЧИ кадров (не имена файлов), она переживает cache-bust/KTX2 переименования нетронутой и по построению отсутствует при repack/merge (без синтеза). Не даёт фиксу молча сломать анимации.

## 5. UI — рентген-кабинет

- **Film-viewer** — герой: снимок атласа с подсвеченными аномалиями (пустота = красный, прозрачность = жёлтый, bleeding = бирюзовый, duplicate-frame = оттенок на кластер, **gutter = info-синие полосы измеренных зазоров, внутренние дыры = жёлтая coarse-карта**), readout из 4 ячеек VRAM/DISK/SIZE/OCC. Оверлеи новых правил честны по построению: gutter-полосы — ровно тот воздух, что вошёл в медиану; карта дыр — только целые грид-ячейки с alpha===0 внутри bbox (строгое недозаявление, кап 64 ректа всё-или-ничего); whole-image факты (upscaled/binary-alpha/gpu-alignment) намеренно БЕЗ оверлея.

## 6. Нативное → бэкенд (opt-in, по умолчанию OFF, согласие, entitlement-gated)

- **KTX2 GPU-compressed текстуры** — Go-сайдкар `toktx` (`apps/encoder`) энкодит `.ktx2` (UASTC + zstd + mips); единственный фикс, режущий реальный **GPU VRAM 4–8×** (невозможно в браузере). Достигается через `apps/api` как entitlement-gated reverse-proxy (держит биллинг-бэкенд тонким). Усиленный сайдкар (non-root, RO-FS, caps, без персистентности, без логирования байт картинок).
- **Измеренный probe VRAM для KTX2** — транскодит произведённый `.ktx2` на пробирующем GPU и считывает реальную сжатую резидентность (инструмент `compressedTexImage2D`); показывается рядом с worst-case ceiling, device-local. Транскодер self-hosted (без CDN-фетча).
- **pngquant lossy-PNG** — 2-я операция сайдкара (256-color квантизация, невозможно в браузере); только диск (никогда заявка на VRAM); decline по quality-floor — kept-not-failed.
- **libvips lanczos3 ресэмпл** — 3-я операция сайдкара, даунскейлящая scale-tier высококачественным ядром, на которое нельзя направить браузерный canvas, заменяя браузерный тайл при ТЕХ ЖЕ размерах/формате; несёт ТОЛЬКО ИЗМЕРЕННУЮ дельту удержания высокочастотной энергии (факт, а не вердикт «резче» — инвариант 3) и НИКАКОЙ заявки на VRAM/диск (инвариант 5). Срабатывает на **каждом реально даунскейленном tier, включая oversize-clamped ВЕРХНИЙ tier** (`dst < src`, не только `tier.scale < 1`), с честной skip-нотой при подавлении content-hash именами.
- **Модель приватности** — ассеты покидают устройство ТОЛЬКО при явном per-run opt-in + согласии (с count/preview загрузки); по умолчанию OFF ⇒ всё остаётся локальным и байт-в-байт.

- **License = опак-ключ; entitlement = ed25519-токен**, верифицируемый **офлайн** в браузере (WebCrypto); device-bound. Кросс-язык байт-контракт fixture (Go ↔ WebCrypto).
- **Pro-гейт по умолчанию OFF** (`VITE_PRO_GATE`) — фикс бесплатен в бете.
- **Локальный деплой** — работает в Docker на этом PC (`:8088`), доступен по Tailscale; подключён к веб-приложению (проверено вживую: activate → sign → offline-verify). Dev-license инструмент (`devmint`) + верификатор подключения.

## 8. CLI + CI

- **CLI `asset-doctor`** — `audit | budget | diff | init` переиспользует ядро в Node (ассеты не покидают машину); exact-dup через `node:crypto`; VRAM = Σ w·h·4.
- **`audit --json|--html|--md|--csv` — все форматы общего отчёта для CI** — из ТЕХ ЖЕ сериализаторов, что кнопки экспорта в вебе (`@asset-doctor/budget` — один источник, ноль дрейфа): `--html` (самодостаточная injection-safe страница), `--md` (Markdown в тело PR — **несёт секцию «Наибольший выигрыш»**), `--csv` (RFC4180-строки находок), `--json` (байт-в-байт как baseline). Любой пишет артефакт при `--out file`, иначе в stdout; **любые два формата вместе — fail-closed конфликт (exit 2)**; без форматного флага `--out` по-прежнему пишет JSON (не ломает).
- **`diff <before> <after>` — детекция регрессий** (чистое ядро `packages/budget/src/diff.ts`): каждый операнд — ПАПКА (аудитится тем же zero-network пайплайном) ИЛИ `audit --json`-файл. Per-metric дельты **измерены** (`after − before`), **disk и каждая VRAM-метрика — отдельные строки, никогда не суммируются** (инв. 5); `pct` опускается при `before = 0` (0→n — новое значение, а не «+∞%»). Находки матчатся стабильным `Finding.id` → added / resolved / **changed** (смена severity — CHANGED, никогда не двойной счёт added+resolved). `--fail-on-new crit|warn|any` — опциональный гейт: exit 1 только на НОВОЙ находке уровня или ухудшенной severity, **никогда на улучшении**; тяжесть метрик тут не гейтится (это `budget --baseline maxDeltaPct` ⇒ diff не переизобретает бюджетирование). Детерминированный JSON + markdown для PR-комментария.
- **GitHub Action budget-gate** — composite `action.yml` с before/after через git worktree; fail-closed JSON-конфиг на browser-only метриках; SARIF/markdown/summary вывод.
- **Sticky PR-комментарий (P9)** — Action постит ОДИН обновляемый на месте комментарий с измеренным before→after диффом (`asset-doctor diff --summary` дословно: дельты метрик, disk/VRAM раздельно + added/resolved/changed по стабильному id). Advisory: шаг до Gate (красный бюджет его не пропускает), все пути best-effort — комментарий никогда не ломает сборку. Inputs `pr-comment`/`github-token`. **Футер «◆ Biggest remaining wins — start here»** — `diff --summary` добавляет наибольшие ОСТАВШИЕСЯ возможности after-состояния (тот же общий `biggestWins`: два раздельных списка диск/VRAM, не суммируются, только положительная измеренная экономия, без тотала) ⇒ PR-комментарий из чистой проверки регрессии становится ещё и гидом «с чего начать дальше». Опущено без `after` или без находок с оценкой (байт-идентично прежнему summary).

## 9. Устойчивость

- **Abortable воркеры** — шов `AbortSignal` через воркеры analyze + fix, чтобы вытесненный drop прекращал конкурировать (аддитивно, по умолчанию off).
- **Честные skip везде** — неразбираемые входы, ошибки энкода, decline по quality-floor, недоступность GPU-формата — всё surfaced (никогда молча), никогда не отгружается больший «оптимизированный» файл.
- **Де-оверлапнутая headline-экономия** — заголовок `potentialDiskSaved` никогда не дважды-считает: format ∩ wasted-alpha ∩ strippable-metadata схлопываются в per-ref MAX, а отброшенные копии exact-duplicate не заявляют ещё и свою format/alpha/strippable-экономию (фантомные байты для файлов, исчезающих при dedup). Всегда ≤ достижимого итога — продукт недообещает, а не завышает.
- **Партиционированный возврат дубликатов** — внутри-атласная frame-redundancy и кросс-атласная redundancy считают НЕПЕРЕСЕКАЮЩИЕСЯ наборы пикселей: собственные внутри-атласные дубли атласа возвращаются один раз (per-rect), а кросс-атласная считает только (distinct-sheets − 1) освобождённых копий, так что оба readout честно аддитивны (каждое сообщённое число равно тому, что соответствующий фикс реально даёт).
- **Устойчивый парсинг multi-page Spine** — границы страниц `.atlas` по КАНОНИЧЕСКОМУ blank-line-контракту libGDX/spine-ts, так что вторая/N-я текстурная страница никогда не отбрасывается молча (без фантомного полностраничного спрайта, без false-orphan изображения). Модерн `offsets` несёт trim-смещение целиком; rotate 180/270 и битая геометрия — malformed+surfaced, а не lossy-парс.
- **Headless e2e-смоук (`pnpm e2e`)** — 11 сценариев в системном Chromium (puppeteer-core, не Playwright — ноль загрузок): одиночный атлас · целая папка · полигональный упаковщик (включается через buildSetting; gate-честно + **pixel-identity mesh-clip-компоуза**: 8/8 спрайтов, 63875 непрозрачных пикселей == источник, 0 расхождений — самый склонный к порче путь фикса, `Blit.clip` ⊆ футпринта и непересекающиеся) · смоук новых поверхностей (кнопка-демо → диагноз · история → дельта · настройки переживают reload · #compare · панель «Наибольший выигрыш» рендерится + клик переводит плёнку · сорт vramWin даёт зелёный VRAM-бейдж) · PWA-офлайн (SW-прекэш + офлайн-диагноз) · направление compose ротации (rotate90-блит == истинный 90° CW-поворот, попиксельно) · **pixel-identity вывода фикса** (скомпонованные спрайты с сохранённым представлением, вкл. trim/rotation, == исходник пиксель-в-пиксель через crop→compose→lossless-WebP) · **активная ротация фикса** (фикс реально поворачивает спрайт на rotation-win-фикстуре; on-page-регион == forward-rotate90 источника — поймал баг, что воркер хардкодил allowRotation:false ⇒ v2 был инертен) · **loose-pack compose** (packLoose пакует 8 отдельных изображений в lossless-лист; каждый упакованный спрайт == исходник пиксель-в-пиксель) · **atlas-merge compose** (aggressive сворачивает два недозаполненных РАЗЛИЧНЫХ атласа в ОДИН lossless-WebP-лист; каждый смердженный спрайт == регион СВОЕГО исходного атласа пиксель-в-пиксель, оригиналы дропнуты — заодно поймал, что фикстура tp-merge отгружала байт-идентичные атласы ⇒ де-дуп вместо мерджа; баг-мерджа не было) · **premultiplied Spine отказ** (pma:true-атлас: репак ОТКАЗАН + surfaced-скип, выходной лист — оригинальные 256² [не рекомпозирован], выходной `.atlas` хранит `pma: true` — canvas не байт-лосслесс для premultiplied, ИЗМЕРЕНО). EN-локаль пинится до загрузки; сборка форсит free-beta-конфиг. Ловит регрессии всего отгруженного UI (нашёл незакрытый `.catch` в FilmViewer на недекодируемых байтах). **Генератор фикстур идемпотентен** — `node fixtures/_generator/generate.mjs` даёт нулевой diff против закоммиченных голденов (устаревшие захардкоженные `expected.json` для bmfont-sparse/tier-source ре-синхронизированы ⇒ regen больше не портит корректные голдены).

## 10. Spine-въювер — интерактивный предпросмотр анимаций (#spine)

- **Отдельный экран `#spine`** — порт всего функционала pixi-spine-viewer в наш дизайн (рентген-кабинет; исходный `styles.js` отброшен). Открывается из сайдбара; ровно один h1 (`ad-spine-h1`), клавиатурно-доступные контролы, reduced-motion стартует на паузе.
- **Локальная загрузка Spine-экспорта** — drag-drop / выбор файлов / выбор папки (File System Access + `webkitdirectory`-фолбэк): скелет JSON + `.atlas` + страницы-картинки, ЛИБО JSON + картинки с синтезированным атласом. Каждый байт читается на устройстве (`createImageBitmap` над dropped-байтами) — ноль сети (инвариант 1).
- **Проигрывание** — play/pause, скорость (timeScale), масштаб отображения; dropdown-ы анимаций и скинов; данные-производные имена анимаций/скинов/слотов рендерятся дословно (никогда не переводятся).
- **Навигация по сцене (v2)** — drag-пан + wheel-zoom скелета (слушатели на `app.canvas`) + кнопка Reset/Fit + полные клавиатурные эквиваленты на фокусируемой сцене (стрелки — пан, `+`/`-` — зум, `0`/`F` — сброс, который обнуляет и Scale ⇒ реально fit-to-frame). Большая сцена-герой (`min-h-[60vh]`).
- **Мульти-трек + комбинированные скины (v2)** — анимации на треках 0..N (анимация/луп/удаление/Empty/default-mix); мультивыбор скинов, комбинируемых через `new Skin('custom')` + `addSkin`. Аккордеон-инспектор Playback/Tracks/Skins/Debug/Slots.
- **Дебаг-оверлеи всех сущностей (v2)** — `SpineDebugRenderer`: кости, region-аттачменты, треугольники/халл мешей, клиппинг, bounding-box-ы, пути, события; тумблеры по умолчанию OFF, цвета из нашей палитры.
- **Слот-маркеры** — навесить/снять круговой маркер на слот + масштаб маркера + **видимость per-marker (v3)**; маркер следует за костью каждый кадр (внутренний Graphics-ребёнок несёт локальный масштаб/видимость — Spine перезаписывает трансформ/visible обёртки per-frame).
- **Индекс слотов + фильтр** — каждый слот с видом аттачмента (mesh/clip/region/bbox/path/point/none), регистронезависимый фильтр (чистая классификация в `lib/spine-inspect.ts`).
- **Очередь анимаций (v3)** — плейлист над треком 0: add/remove/clear/loop, автопродвижение на `complete`-листенере, подсветка текущего; finished-курсор паркуется на length (лупящаяся последняя запись даёт `complete` каждый цикл — очередь честно останавливается при loop-OFF).
- **Таймлайн + скраб + трим (v3)** — readout времени/длительности, labeled range-скраббер (мышь и клавиатура), трим-цикл под-диапазона [start,end] чистым trackTime-wrap; трим ре-клампится при смене анимации. **FPS-бейдж** (реальный `ticker.FPS`) + **альфа на трек** (`TrackEntry.alpha`, переживает автопродвижение).
- **Инспектор костей + гранулярный дебаг (v3)** — фильтруемый список костей с per-bone подсветкой (line+dot глифы, координаты зеркалят SpineDebugRenderer); пер-сущностный выбор regions/meshes/paths/bboxes/clipping (счётчики, All/None, фильтр) — рисуются только выбранные, рядом с глобальными v2-тумблерами; подсветка региона — честный контур (без публичного per-slot контейнера в spine-pixi-v8).
- **Pixi v8 + spine-pixi-v8** — движок на официальном рантайме `@esotericsoftware/spine-pixi-v8` (async `Application.init`, `SpineTexture.from(source)` per page, `SkeletonJson.readSkeletonData` → `new Spine(skeletonData)`, `Physics.update`-энум). Импер-движок вне React-дерева (`lib/spine-engine.ts`); чистая логика (группировка файлов / atlas-munging / фильтр слотов) — в Node-тестируемом `lib/spine-files.ts` (23 теста; у web нет Pixi-харнесса ⇒ рантайм проверен build/typecheck). Страничные текстуры освобождаются при перезагрузке (`Texture.destroy(true)`) — без утечки VRAM (инвариант 5). +32 i18n-ключа ×10 + чек-лист ручного браузер-теста.
