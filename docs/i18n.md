# Internationalization (i18n)

Full localization of the **web app** and the **extension overlay** — UI chrome *and* the diagnoses
themselves — in 9 languages: English (source), Russian, German, Spanish, Portuguese (BR), French,
Italian, Simplified Chinese, Hindi. The CLI stays English (a dev/CI tool).

## Architecture

Zero runtime dependency. The shared package **`@asset-doctor/i18n`** holds a flat key→template catalog
per locale plus a tiny renderer:

- `translate(locale, key, params)` — interpolates `{name}` / `{name:hint}` (hints: `:bytes :mb :pct
  :sev`) and selects plural forms via the browser-native `Intl.PluralRules`.
- `renderFinding(finding, locale)` / `renderCorrelated(finding, locale)` — turn the analysis/correlate
  `messageKey` + `params` into localized `{title, detail, fix}`.
- `detectLocale()`, `NATIVE_NAME`, `LOCALES`, `isLocale`.

Both surfaces import it: the web wraps it in a React context (`apps/web/src/lib/i18n.tsx`,
`<I18nProvider>` + `useI18n()`), the extension calls it directly in the MAIN-world overlay. One catalog
source, no duplicated translations.

## Findings carry data, not English

Localizing the *diagnoses* (the moat's core value) without breaking the "analysis is objective" rule:
the analysis/correlate rules now attach an optional **`messageKey` + `params`** to each finding (raw
numbers, e.g. `{ occ: 0.4, w: 2048, vram: 16777216 }`). The presentation layer renders them per locale.
The change is **additive** — the baked English `title`/`detail`/`fix` stay as the source-of-truth and
the i18n fallback, so the CLI / JSON output and all existing tests are untouched.

English is rendered from the catalog too, and a **drift-guard test** runs every real rule and asserts
`renderFinding(f,'en')` is byte-identical to the baked string — so a template can never silently
diverge from what the analyzer produces. A **completeness test** asserts every locale has exactly the
English key set with matching placeholders and valid plural objects.

## Translations

Generated by a per-language workflow (one agent per language) that translates the English catalog,
preserving every placeholder, format hint, symbol, and plural category (`Intl.PluralRules` categories:
ru = one/few/many/other, zh = other only, etc.). A post-processor validates each result — parsing
plural objects, checking placeholder sets match English exactly, reverting any mismatched key to English
(graceful degradation; a missing key always falls back to English). All 9 catalogs: 105/105 keys.

## Switching

Auto-detect from `navigator.languages`; a header `<select>` (web) / overlay `<select>` (extension) lets
the user pick any of the 9 (shown in each language's own name). The web persists the choice to
`localStorage`.

## Verify

- `pnpm --filter @asset-doctor/i18n test` — drift guard + completeness.
- `tools/verify/i18n-run.mjs` — web: locale-from-storage, switcher across scripts, localized findings.
- `tools/verify/ext-i18n-run.mjs` — extension: localized HUD + correlation cards.

## Follow-ups

The extension bundles all 9 catalogs into the content script (~190 KB); lazy-loading per locale is a
possible optimization. Severity tags (crit/warn/ok/info) are kept short/English by convention.
